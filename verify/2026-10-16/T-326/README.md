The supported gate profile resolves inline driver rules by unique rule ID or an explicit nonnegative integer index. When both ID/index are supplied, they must identify the same descriptor. Duplicate IDs require an index. SARIF permits a result ID equal to its descriptor ID plus one additional slash-separated hierarchical component; the matcher permits exactly that relation, not arbitrary string-prefix equivalence. See [OASIS SARIF 2.1.0 sections 3.27.5–10, 3.50.3 and 3.52.4](https://docs.oasis-open.org/sarif/sarif/v2.1.0/os/sarif-v2.1.0-os.html). Tests include exact IDs, conflicting IDs/indexes and the valid x/detail relation. Explicit result severity wins; absent failure severity inherits the rule default then warning. Non-failure kinds have none severity and are not failed findings.

The gate conservatively rejects unsupported extension/GUID rule references, invocation configuration overrides and external property files rather than pretending those metadata resolve to warning. It retains the existing minimal clean/scalar-result compatibility profile; it is not a complete SARIF schema validator or generic external-file resolver. Numeric severity still blocks failure findings at 7 or higher. Invalid numeric/level/kind/identity data does not become clean. Result suppressions and disabled rule configuration do not waive a failing finding.
