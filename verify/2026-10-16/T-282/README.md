# T-282 authenticated atomic archive append

The appender authenticates incoming source proof through build_record and the reviewed exclusive-App/bootstrap gate through separate source/state clients. It binds actual source/store repository ID/privacy, fixed per-repository archive stream and same run/attempt identity (artifact replacement cannot create a new identity). Immutable identity payloads bind exact record hash and sequence. Numeric paths use strict3/3/3prefix sharding/full12digit filenames, avoiding a near-term flat index directory limit. Record/material blobs, both indices and discovery count share one observed-base tree, unique single-parent commit and non-forced branch CAS. No runtime task transition or merge permission exists.

Actual RED captured missing append implementation. Additional actual REDs showed lost-ack/network uncertainty was not labelled, same-name foreign repository IDs were not blocked and writer policy changes during staging were accepted. Final GREEN passes11 real Git scenarios: immutable object/tree writes, non-fast-forward ref conflict and rebase, encrypted/foreign checkpoint preservation, lost acknowledgement and restart idempotency, same-attempt artifact conflict, three-conflict exhaustion without journal advancement, foreign state/stream rejection, lost acknowledgement plus inaccessible reconciliation, two simultaneous archive writers preserving both sequence updates, foreign source ID rejection and protection drift before ref update. Fixture APIs model repository/protection metadata; real disposable Git commands create blobs/trees/commits and enforce ref CAS. This is not live GitHub App or archive proof.

Object sizes and immutable conflicts are checked before blob upload; provider response/identity/parent checks precede confirmed progress. A ref failure may have committed, so retries re-observe protected origin and reconcile up to three attempts. Missing discovery over an existing stream never resets origin. Shared checked API observations are capped32MiB, with conservative source-file accounting; provider adapters retain transport bounds. Exact inert write endpoints cannot publish checks or merge. Content hashes are integrity, never origin by themselves.

The legacy recursive GitState constructor is not used for archive append. Bootstrap still requires complete bounded origin verification; T-284 authenticated incremental anchors/cursors remain necessary for long histories, and partial cursor JSON never grants trust. Archive-enabled reporting integration remains future work. Existing normal reporting and feedback remain unchanged; private key copying, PAT/App credential migration and live update restrictions require separate operator review. No source profile/default flag, workflow, credential, live bootstrap or branch was changed.
