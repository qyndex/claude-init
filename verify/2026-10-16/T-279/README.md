# T-279 bounded compact receipt proof

Builder calls actual receipt authentication against its API adapter; it does not accept an authenticated flag or caller-supplied proof. It retains the original receipt ZIP/digest, immutable run/attempt/workflow/source execution facts, artifact run/repository/head-repository/head-SHA origin, selected profile ID/canonical document hash, and deduplicated exact policy/spec/runtime/trust material. Re-fetches must match authenticated execution and source facts. Private source requires a private destination; output excludes arbitrary provider logs/Slack plaintext fields.

Validation checks exact nested data schemas, receipt delivery semantics, approved selected profile or explicit legacy binding, source policy/spec/runtime equality, ZIP digest/single bounded member, base64 and material hashes, exact material set, foreign metadata, record identity conflicts and private/public constraints. Record and each object are bounded to 1 MiB; receipt decompression is 256000 bytes/one member; at most nine material objects (9 MiB, below 32 MiB invocation budget). Only exact compact metadata/source material is retained. The original detailed review/provider output is not copied.

Integrity validation DOES NOT establish external origin: hashes and internally consistent JSON alone are insufficient. Protected archive bootstrap/chain, approved store origin and CAS append are future T-280–282; no archive storage or projection was activated. The conflict comparator requires already-validated records. Retention remains indefinite compact proof; detailed Actions artifacts remain 90 days.
