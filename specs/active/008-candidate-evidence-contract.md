# Candidate evidence contract

Implements F-02's deterministic validation core under the operator-approved factory plan. This is a preparation for trusted GitHub Actions and a dedicated GitHub App, not an activation of merge authority.

## Acceptance criteria

1. **AC-1**: Evidence must bind exactly to repository, pull request, candidate head, base, spec revision and policy revision supplied by an authoritative coordinator. Ancestor proofs, missing/extra/duplicate AC IDs and malformed documents fail.
2. **AC-2**: Every expected AC requires a passing observation and an artifact SHA-256. Required check receipts match the exact head, successful completed runs and configured producer App IDs. Missing, duplicate, unexpected or skipped checks fail.
3. **AC-3**: Separate verification and review verdicts both pass, have no unresolved findings and identify different allowed actors, neither the implementer. All verdicts bind to the same candidate. Evidence timestamps are bounded by the coordinator's run window.
4. **AC-4**: Regression fixtures cover valid evidence and mutations of all authority boundaries without calling models or GitHub. Documentation explicitly distinguishes structural checks from authenticated attestation.

## Trust boundary

The context file MUST be generated by a protected coordinator from authenticated GitHub API data and approved spec/policy storage, never accepted from PR content. This validator does not authenticate signatures or download artifacts. Passing it alone is insufficient to merge. Existing merge routes remain ineligible for factory activation until F-03 routes all decisions through authenticated receipt retrieval and this contract.
