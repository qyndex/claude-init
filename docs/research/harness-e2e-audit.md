> **Date:** 2026-06-12 · **Method:** dynamic workflow `e2e-harness-audit` (run wf_55a2650a-aac) — 14 domain-expert auditors (greenfield, brownfield, spec pipeline, TDD loop, autopilot, swarm, hooks, security-under-auto-mode, CI gates, E2E rig, stack portability, release/deploy, failure recovery, docs truth), each finding adversarially re-verified by an independent same-expertise skeptic against the actual files. 29 agents, ~1,140 tool uses.
> **Question asked:** can this harness take a real app — greenfield or brownfield — from spec to shipped, end-to-end, in auto mode, as solidly as Claude Code itself?

> **Result:** **77 findings survived verification** (12 adjusted, 65 confirmed; refuted findings dropped) — 9 critical, 36 high, 3 low, 29 medium.

## Executive summary

The 77 confirmed findings cluster into five failure families: (1) the deterministic security layer is simultaneously bypassable (MCP writes, npx, cat|sh, jq fail-open) and over-blocking (exec/eval/UUID false denies are terminal in Auto Mode), and the constitution guard denies the very TASKS.md/specs writes every inner-loop agent needs; (2) the verification/merge spine is structurally red — evidence-gate cannot pass on any real project (ignored SKIPs, gitignored ledger logs, no toolchain install, no app server, web-only AC proof, factory state shipped into fresh projects, silent PASS on non-big-4 stacks); (3) the autonomous loop's state machine is prose — picker is dep/priority/template-line-blind, loop-control and budgets have no driver, analyze gate has no producer, crashes orphan [~] tasks, and a stop-gate livelock burns overnight budget; (4) swarm and release last-mile are wired to paths that never converge (worktree-local gitignored state, dead claude -p invocations, no PR/CI wait, no auto-merge policy, no ramp driver, no executable rollback); (5) docs/ops drift. The plan fixes auto-mode safety first (a harness that can hurt or wedge itself unattended must be grounded before its gates are tightened), then the merge/verification spine (so green means green and red is reachable-fixable), then mechanizes the loop, then swarm/brownfield/release convergence, then robustness and doc truthfulness. Two load-bearing early decisions gate many items: the lock-safe task-status write path (P1) and the ledger-evidence storage format (P2), each consumed by 4+ later fixes.

### hooks-engineering-1 [high] pre-bash-guard blocks common legitimate commands (exec/eval/python-c substring match + quoted-content segment split) — a terminal deny in Auto Mode

Empirically (guard fed via jq): `pnpm exec vitest run`, `docker compose exec svc test`, `kubectl exec -it pod -- ls`, `git commit -m "why eval is banned"`, `git commit -m "forbid python -c here"`, `npx playwright test --grep "exec path"`, and `rm -rf /tmp/build-cache` ALL returned exit 2 (hard block). ### hooks-engineering-4 [medium] pre-bash-guard fails OPEN on malformed stdin: `set -euo pipefail` + unguarded jq aborts the guard before any pattern check

- **Why we need it:** The guard is the deterministic first line of defense in Auto Mode.
