# GitHub-hosted delivery reporting

The pilot uses standard GitHub-hosted Actions with a dedicated `factory-reporting-state` data branch in `qyndex/claude-init`. No reporting VM is required. Adopters choose their own repository/branch and Slack destination; source repository defaults to the adopting workflow's `github.repository`, never qyndex. The existing self-hosted profile remains optional and requires an explicit different profile selection.

## Durable state and public boundary

`.claude/scripts/factory-git-state.py` exports only typed digest cursors, immutable origin, batches and receipts as JSON under `reports/<stream-sha256>.json`. It does not upload SQLite files, arbitrary tables, operator feedback or credentials. The public pilot state contains public PR titles/merge identities, evidence links and Slack delivery metadata. Every source PR is read from the configured repository; private source repositories require a private state repository. Anyone can read public pilot records; public visibility does not grant write permission.

A data branch accepts only README and report JSON blobs, never workflows, executable files, symlinks or runtime code. Missing/corrupt/incomplete state blocks rather than creating a new cursor. First bootstrap requires the exact initial empty data-branch SHA. The branch must have active deletion and non-fast-forward rules with no bypass actors. Administrators and authorized state writers remain trusted; state history must not be rewritten or deleted to reset reports.

Each changed snapshot creates a blob, tree and uniquely named commit from the observed parent. A non-force reference update rejects a competing divergent writer. Commit uniqueness is required even when snapshot bytes are identical. Failed projections cannot continue; the next job restores the authoritative branch. The uncertain-send snapshot must succeed before Slack is called. A lost Slack reply reconciles by bot/key/hash/text on the next runner. A lost state acknowledgement likewise restores the actual branch; no blind rebase, force push or resend occurs. [GitHub reference API](https://docs.github.com/en/rest/git/refs) documents the non-force fast-forward update. The current snapshot limit is 8 MB; reaching it blocks rather than discarding report history. Retention/compaction is future work.

## Bootstrap and activation

1. Create a data-only orphan branch with a public README, separately from the code/default branch. Record its initial commit SHA. Add an active ruleset scoped exactly to that branch with `deletion` and `non_fast_forward`, and no bypass actors. Do not modify default-branch merge protections. A repository with incompatible global PR/check rules must configure a permitted machine state branch rather than bypassing those rules.
2. In the main/default-branch-only `factory-reporting` environment, set channel, team ID, timezone-bearing initial `FACTORY_REPORTING_START`, `FACTORY_REPORTING_STATE_BRANCH`, and `FACTORY_REPORTING_BOOTSTRAP_SHA`. Optional `FACTORY_REPORTING_STATE_REPOSITORY` defaults to the adopter's repository. Never reset start/bootstrap to repair a failed delivery. For same-repo state the Actions token is sufficient; optional other-repo state requires `FACTORY_REPORTING_STATE_TOKEN` limited to that state repository's contents write permission.
3. Store `FACTORY_SLACK_BOT_TOKEN` as an environment secret and invite its bot to the intended channel. The bot needs documented write/history scopes for exact uncertain-send reconciliation. No merge App key or organization runner-policy credential is needed by this profile.
4. Set repository-level `FACTORY_REPORTING_PROFILE=github-hosted`. Keep repository-level `FACTORY_REPORTING_ENABLED` unset until source/ref/state protection and live positive/negative identity/delivery drills pass. Both workflows share a concurrency group and have mutually exclusive profile guards. Changing an already active profile/store requires verified state migration preserving receipts and uncertainty; the pilot has never sent a report and needs no migration.
5. After prerequisites and drills, dispatch the hosted workflow from the default branch and inspect the actual message and durable confirmed checkpoint before relying on recurring delivery. Periodic UTC scheduling selects the latest 08:00 Sydney cutoff using DST-aware due-time logic; GitHub queueing can delay execution. Workflow failure exposes blocked delivery; external missed-schedule notification remains an operational integration.

The hosted job has contents write for data commits and PR read for source queries. It checks out trusted source SHA without persisted credentials and uses a protected reporting environment. It never executes candidate code. Default-branch protection continues to block direct code changes; no policy/admin/PR-write permission or merge App secret is granted. The initial profile supports github.com; enterprise hosting needs a separately verified endpoint adapter.

Live Slack credentials, authenticated identity/send drills and authoritative receipt ingestion into reporting remain separate readiness items. Missing historical proof is reported explicitly rather than fabricated. Fixtures exercise a Git API model and real local SQLite/digest transport boundaries; they do not constitute an authenticated independent reviewer receipt or a live GitHub/Slack send. Rollback uses a protected code revert, disables the master variable first, and preserves the state branch and confirmed delivery history.
